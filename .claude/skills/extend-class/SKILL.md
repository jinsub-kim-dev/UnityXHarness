**$ARGUMENTS** — 기존 클래스를 확장한다.

## 핵심 원칙: 기존 코드를 지키고 유지한다

- 먼저 대상 클래스 파일과 같은 폴더의 관련 파일(Manager·Module·Interface)을 **읽고** 현재 구조를 파악한다
- 그 클래스가 **이미 따르고 있는 패턴**(네이밍, 의존성 주입 방식, R3 사용, 메서드 구성)을 그대로 따른다. 새로운 스타일을 끌어들이지 않는다
- 기존 코드의 동작을 바꾸지 않는다. 요청한 기능 추가에 필요한 최소한만 수정한다
- 기존 메서드 시그니처·public API를 함부로 바꾸지 않는다. 바꿔야 한다면 멈추고 사람에게 먼저 확인한다
- 관련 없는 리팩토링·포맷 정리·주석 추가를 끼워넣지 않는다

## 확장 방향 판단 → 적절한 Skill로 라우팅

추가할 기능의 성격에 따라 단순히 기존 클래스에 직접 넣을지, 새 단위를 만들어 연동할지 판단한다.

- **기능이 1~2개로 단순** → 대상 클래스(Manager 등)에 메서드를 직접 추가
- **로직 단위가 커지거나 재사용·분리가 필요** → 새 Module을 만들어 위임. `add-module` Skill로 라우팅한 뒤 대상 Manager가 소유·위임하도록 연결
- **새로운 전역 Manager가 필요** → `add-global-manager` Skill로 라우팅
- 어디에 넣을지 애매하면 코드 작성 전에 사람에게 먼저 확인한다
- 대상이 `00_CommonFramework`의 클래스면 수정 전에 사람 승인을 받는다 (공통 코드)
- 새로 생기는 파일은 `Assets/10_ProjectA/00_Script/...`, 작성 규칙은 `csharp-convention-guide` Skill을 따른다

## 확장 후 검증

- 기존 의존 방향(Manager → Module, Manager →(interface)→ Service)을 깨지 않았는지 확인
- 기존 코드의 기존 동작이 그대로 유지되는지 확인
- CLAUDE.md 금지 패턴 위반 없는지 확인
